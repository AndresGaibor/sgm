# tMSSqlSP

Offers a convenient way to centralize multiple or complex queries in a database and calls them easily.

tMSSqlSP calls the stored procedure in a Microsoft SQL Server or Azure SQL database.

## tMSSqlSP Standard properties

These properties are used to configure tMSSqlSP running in the Standard Job framework.

The Standard tMSSqlSP component belongs to the Databases family.

The component in this framework is available in all Talend products.

Information noteNote: This component is a specific version of a dynamic database connector. The properties related to database settings vary depending on your database type selection. For more information about dynamic database connectors, see [DB Generic components](https://help.qlik.com/talend/r/en-US/8.0/components/db-generic/db-generic-component).

Information noteNote: When building a Job as an OSGI Bundle for ESB, MS SQL Server drivers jtds and mssql-jdbc used by the SQL Server components are not included in the build artifact. To run the artifact in Talend Runtime, you need to deploy the drivers manually by copying the drivers to the &lt;TalendRuntimePath&gt;/lib folder and restart Talend Runtime.

## Usage

| Usage guidance | Description |
| --- | --- |
| Usage rules | This component is used as intermediary component. It can be used as start<br>component but only input parameters are thus allowed.<br><br>Information noteImportant:<br>Microsoft SQL Server/JDBC encryption requirements<br><br>Starting with recent<br>versions of the Microsoft SQL Server JDBC driver, TLS encryption is enabled<br>by default (encrypt=true;trustServerCertificate=false).<br>This enhances security, but if your SQL Server does not support encrypted<br>connections or does not require clients to use TLS, you must set<br>encrypt=false in the JDBC parameters of this component<br>to connect successfully.<br><br><ul> <li> <p>For production or cloud environments using certificates signed by a                              trusted authority (e.g., Azure, AWS), no changes are needed, the                              default settings will work. </p> </li> <li> <p>For servers using self-signed certificates, use                                 <span>encrypt=true;trustServerCertificate=true</span> or                              specify the trust store details                                 (<span>encrypt=true;trustStore=&lt;your_trust_store&gt;;trustStorePassword=&lt;your_trust_store_password&gt;</span>).                           </p> </li> <li> <p>For non-secure development or test servers, set                                 <span>encrypt=false</span> in the additional JDBC parameters.                           </p> </li> </ul><br><br>For more information on how to use connections with encryption<br>properties, see [Microsoft SQL JDBC documentation](https://learn.microsoft.com/en-us/sql/connect/jdbc/connecting-with-ssl-encryption?view=sql-server-ver17). |
