# tMSSqlConnection

Opens a connection to the specified database that can then be reused in the subsequent subJob or subJobs.

tMSSqlConnection opens a connection to a Microsoft SQL Server database or a Microsoft Azure SQL database.

## tMSSqlConnection Standard properties

These properties are used to configure tMSSqlConnection running in the Standard Job framework.

The Standard tMSSqlConnection component belongs to the Databases and the ELT families.

The component in this framework is available in all Talend products.

Information noteNote: This component is a specific version of a dynamic database connector. The properties related to database settings vary depending on your database type selection. For more information about dynamic database connectors, see [DB Generic components](https://help.qlik.com/talend/r/en-US/8.0/components/db-generic/db-generic-component).

Information noteNote: When building a Job as an OSGI Bundle for ESB, MS SQL Server drivers jtds and mssql-jdbc used by the SQL Server components are not included in the build artifact. To run the artifact in Talend Runtime, you need to deploy the drivers manually by copying the drivers to the &lt;TalendRuntimePath&gt;/lib folder and restart Talend Runtime.

| Auto Commit | Select this checkbox to commit any changes to the database automatically<br>upon the transaction.<br><br>With this checkbox selected, you cannot use the corresponding commit<br>component to commit changes to the database; likewise, when using the<br>corresponding commit component, this checkbox has to be cleared. By default, the<br>auto commit function is disabled and changes must be committed explicitly using<br>the corresponding commit component.<br><br>Note that the auto commit function commits each SQL statement as a<br>single transaction immediately after the statement is executed while the<br>commit component does not commit only until all of the statements are<br>executed. | Share identity insert in multi table | Select this checkbox to share IDENTITY\_INSERT among multiple<br>Microsoft SQL tables that accept data through the same database connection.<br><br>This option prevents errors caused by setting IENTITY\_INSERT to ON (or OFF) repeatedly<br>when writing Microsoft SQL tables through a database connection. | tStatCatcher Statistics | Select this checkbox to gather the Job processing metadata at a Job level as<br>well as at each component level. |

## Usage

| Usage guidance | Description |
| --- | --- |
| Usage rules | This component is more commonly used with other tMSSql\* components,<br>especially with the tMSSqlCommit and<br>tMSSqlRollback components.<br><br>Information noteImportant: Microsoft SQL Server/JDBC encryption requirements<br><br>Starting<br>with recent versions of the Microsoft SQL Server JDBC driver, TLS encryption<br>is enabled by default<br>(encrypt=true;trustServerCertificate=false). This<br>enhances security, but if your SQL Server does not support encrypted<br>connections or does not require clients to use TLS, you must set<br>encrypt=false in the JDBC parameters of this component<br>to connect successfully.<br><br><ul> <li> <p>For production or cloud environments using certificates signed by a                              trusted authority (e.g., Azure, AWS), no changes are needed, the                              default settings will work. </p> </li> <li> <p>For servers using self-signed certificates, use                                 <span>encrypt=true;trustServerCertificate=true</span> or                              specify the trust store details                                 (<span>encrypt=true;trustStore=&lt;your_trust_store&gt;;trustStorePassword=&lt;your_trust_store_password&gt;</span>).                           </p> </li> <li> <p>For non-secure development or test servers, set                                 <span>encrypt=false</span> in the additional JDBC parameters.                           </p> </li> </ul><br><br>For more information on how to use connections with encryption<br>properties, see [Microsoft SQL JDBC documentation](https://learn.microsoft.com/en-us/sql/connect/jdbc/connecting-with-ssl-encryption?view=sql-server-ver17). |
