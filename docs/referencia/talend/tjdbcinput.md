# tJDBCInput

Reads any database using a JDBC API connection and extracts fields based on a query.

tJDBCInput executes a database query with a strictly defined order which must correspond to the schema definition. Then it passes on the field list to the next component via a Main row link.

### In this section

* [tJDBCInput Standard properties](https://help.qlik.com/talend/en-US/components/8.0/jdbc/tjdbcinput-standard-properties)

| Enable partitioning | Select this check box to read data in partitions.<br><br>Define, in double quotation marks, the following parameters to configure the<br>partitioning:<br><br><ul> <li> <p> <span>Partition column</span>: the numeric column                     used as partition key.</p> </li> <li> <p> <span>Lower bound of the partition stride</span>                     and <span>Upper bound of the partition                        stride</span>: enter the upper bounds and the lower bound to determine                     the partition stride. These bounds do not filter the table rows. All rows in                     the table are partitioned and returned.</p> </li> <li> <p> <span>Number of partitions</span>: the number of                     partitions into which the table rows are split. Each Spark worker handles only                     one of the partitions at a time.</p> </li> </ul><br><br><br>The average size of the partitions is the result of the difference between the<br>upper bound and the lower bound divided by the number of partitions, that is to say,<br>(upperBound - lowerBound)/partitionNumber, while the first and the last partitions also<br>include all the other rows that are not contained in the other partitions.<br><br>For example, to partition 1000 rows into 4 partitions, if you enter 0 for<br>the lower bound and 1000 for the upper bound, each partition will contain 250 rows<br>and so the partitioning is even. If you enter 250 for the lower bound and 750 for<br>the upper bound, the second and the third partition will each contain 125 rows and<br>the first and the last partitions each 375 rows. With this configuration, the<br>partitioning is skewed. |
