# MG-P10-01: agregados PROC SQL — plan de implementación

> **Para agentes de implementación:** usar `superpowers:executing-plans`; los pasos usan casillas para seguir el avance.

**Objetivo:** ejecutar los agregados SAS documentados que aparecen en la IR y cerrar `l2_08_case_when_tras_left_join` en el anillo B.

**Arquitectura:** `interprete_agregados.agregar(filas, params, ...)` aplicará `GROUP BY` sobre las filas recibidas y evaluará solo `COUNT(*)`, `COUNT(expresión)`, `SUM`, `AVG`, `MIN` y `MAX`. La IR conserva `group_outputs` y `output_order` para que la salida coincida con el `SELECT`; `lower_sql_flow` marca la remezcla no implementada como pendiente. El intérprete inyecta el parser y evaluador y adapta los rechazos a `NoSoportadoEnInterprete`. Se conecta como operador y como paso de `map`.

**Tecnologías:** Python 3, `sqlglot`, pytest y Ruff; sin dependencias nuevas.

**Diseño:** `docs/superpowers/specs/2026-11-09-mg-p10-01-agregados-design.md`.

## Restricciones globales

- No inventar tipo ni equivalencia: clave de grupo texto numérico sin tipo demostrado queda no soportada.
- No modificar `esperado/`; no borrar ni debilitar pruebas.
- El intérprete no se conecta a bases ni agrega dependencias.
- Hito con commit local `hito 128: interpretar agregados PROC SQL en el anillo B`; no hacer push.

## Revisión prioritaria

1. `COUNT(*)` cuenta todas las filas aunque haya otros campos faltantes.
2. `COUNT(expresión)` omite faltantes; `SUM`, `AVG`, `MIN` y `MAX` omiten faltantes y devuelven faltante si no queda ningún valor.
3. `GROUP BY` consolida claves faltantes y conserva claves distintas; grupos de texto numérico ambiguo se rechazan.
4. Un agregado sin `GROUP BY` produce una fila resumen, incluso para entrada vacía; grupos con `GROUP BY` sobre entrada vacía producen cero filas.
5. Agregados no cubiertos y `GROUP BY` sin agregado se rechazan de forma explícita.
