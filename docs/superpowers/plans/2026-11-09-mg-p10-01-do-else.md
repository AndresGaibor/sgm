# MG-P10-01: ejecutar `IF ... THEN DO` con `ELSE` — plan de implementación

> **Para agentes de implementación:** SUBHABILIDAD OBLIGATORIA: usar `superpowers:executing-plans` para implementar este plan tarea por tarea. Los pasos usan casillas (`- [ ]`) para seguir el avance.

**Objetivo:** cerrar el caso conocido `l0_13_do_end` del anillo B al conservar la rama `IF/THEN DO/ELSE` como asignaciones condicionales en la IR.

**Arquitectura:** el lowering del DATA step reconocerá solo un `IF ... THEN DO` con asignaciones simples, `END` y `ELSE` de asignación. El parser guarda `IF ... THEN DO` como una sentencia; el grupo empieza en la sentencia siguiente. Emitirá el metadato `conditional` que consumen el intérprete y el emisor Talend. Cualquier forma fuera de ese subconjunto conserva el fallback parcial actual.

**Tecnologías:** Python 3, pytest y Ruff; sin dependencias nuevas.

**Diseño:** `docs/superpowers/specs/2026-11-09-mg-p10-01-do-else-design.md`

## Autorrevisión

- Las sentencias dentro del bloque se agrupan solo si todas son asignaciones simples y sus destinos no se repiten; el parser no se apropia de `OUTPUT`, `DELETE`, `DO` anidado ni otra forma.
- El intérprete y el emisor ya leen la metadata `conditional`; el test del caso B y `test_desde_plan.py` detectan regresiones de los dos consumidores.
- El esperado existente es la referencia independiente; no se modifica.
