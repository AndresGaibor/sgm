# Plan de implementación MG-P13-04: SBOM

> **Para agentes:** ejecutar las tareas en orden y marcar cada una al completarla.

**Objetivo:** Generar `docs/sbom.md` y un SPDX 2.3 completo y verificable desde el lock del proyecto.

**Arquitectura:** Un generador con biblioteca estándar lee `pyproject.toml` y `uv.lock`, conserva cada variante de resolución y el alcance runtime/desarrollo, y escribe el inventario Markdown, SPDX 2.3 y un manifest con la correspondencia archivo/URL/hash de cada distribución.

**Tecnologías:** Python 3.12, `tomllib`, `json`, `hashlib`/`importlib.metadata`, pytest, Ruff.

**Especificación:** `docs/superpowers/specs/2026-11-10-mg-p13-04-sbom-design.md`

## Restricciones

- No agregar dependencias.
- No afirmar licencias no demostradas; usar `NOASSERTION` si no existe declaración verificable.
- No inspeccionar ni copiar secretos o datos del cliente.
- No hacer `git push`; un commit local por hito.

## Enfoque de revisión

- Paquete fijado sin metadata local instalada: conservar versión/hash del lock y declarar licencia pendiente.
- Dependencia condicional por plataforma: incluirla desde el lock sin omitir variantes.
- Referencia a un nombre con varias variantes: resolver por versión/origen; fallar si queda ambigua.
- Paquetes compartidos entre runtime y desarrollo: marcar ambos alcances.
- Licencia dual expresada como OR: preservar la expresión SPDX completa.
- Cambio de un hash de distribución: regenerar el SBOM y hacer fallar la prueba si queda obsoleto.
